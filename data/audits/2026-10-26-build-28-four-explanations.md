원본 PDF 154~157쪽에서 표·상태도·C 코드를 직접 판독하고 기존 답안과 비교했다.

## 2026-B-06

- 검증 수준: 원본 상태도·코드 직접 확인; 가능한 스케줄 구성. 공식 채점기준 미대조

원본 PDF 154쪽의 상태도와 1~11행 코드를 대조했다.
1. 고아 프로세스는 부모가 먼저 종료했지만 자식은 아직 살아 있는 상황이다. 가능한 스케줄 하나를 고르면 자식은 5행 printf를 끝내고 준비 상태로 남아 있고, 부모는 7행 printf와 10행 return 0, 11행 닫는 중괄호까지 진행해 종료 상태가 된다. 따라서 부모 (11, 종료), 자식 (5, 준비)이다.
2. 8행에 wait(&status)를 넣으면 부모는 자식 종료 상태를 회수하려 한다. 좀비가 나타날 수 있는 시점은 자식이 11행까지 마쳐 종료된 반면 부모가 아직 wait를 실행하지 않은 순간이다. 예컨대 부모는 7행 printf를 마치고 준비 상태, 자식은 11행까지 실행하고 종료 상태인 경우다. 부모 (7, 준비), 자식 (11, 종료).
3. 두 예시는 가능한 실행 순서 중 하나다. 스케줄러가 다른 순서를 택하면 고아나 좀비가 발생하지 않을 수 있으며, 그림의 노드 명칭을 벗어나 임의의 상태를 답으로 사용해서는 안 된다.

## 2026-B-08

- 검증 수준: 원본 회로 판독·2의 보수 계산 독립 확인. 공식 채점기준 미대조

원본 PDF 155쪽의 MUX와 디코더 선택선을 확인했다.
1. 레지스터 번호는 2비트이므로 R1의 번호는 01, R3의 번호는 11이다. R1을 MUX1에 넣는 SELA=01, 결과 목적지 R3를 지정하는 SELC=11이다.
2. R1=0110은 +6, R2=0100은 +4. 덧셈의 5비트 결과는 01010이므로 4비트 레지스터에 저장되는 값은 하위 4비트 1010이다.
3. 4비트 2의 보수 표현 범위는 −8~+7이다. +6과 +4의 합 +10은 범위를 넘는다. 최상위 부호 비트로 들어오는 캐리 C3와 나가는 캐리 C4의 배타적 논리합 V=C3 XOR C4가 1이므로 부호 있는 덧셈 오버플로다.

## 2026-B-10

- 검증 수준: 원본 코드 직접 판독 및 gcc 독립 실행 확인. 공식 채점기준 미대조

원본 PDF 156쪽의 C 코드를 재구성하여 gcc(C11)로 실행 검산했다.
1. 최소 힙의 자식 2개 중 작은 키를 선택해야 하므로 ㉠은 child < n && list[child] > list[child+1]이다. 오른쪽 자식 인덱스가 n을 넘지 않아야 한다는 경계조건이 필수다.
2. 힙에서 루트와 마지막 원소를 교환한 후 정렬 완료 위치는 힙에서 제외한다. 반복 변수 i가 남은 힙 크기이므로 ㉡은 makeHeap(list, i, 1)이다.
3. 초기 배열 {0,10,30,20,40,1,50,70}을 바닥에서부터 최소 힙으로 만들면 힙 구간 인덱스 1~7은 {1,10,20,40,30,50,70}이다. 따라서 ⓐ list[4]는 40을 출력한다.
4. 최소값 20이 루트에서 추출되는 회차의 힙 조정 이후 list 배열에서 값 40의 위치는 인덱스 2이므로 ⓑ는 2를 출력한다. 실제 컴파일·실행 결과도 40과 2였다.

## 2026-B-11

- 검증 수준: 원본 학생·지도 코드 직접 판독 및 정수 나눗셈과 fall-through 검증. 공식 채점기준 미대조

원본 PDF 157쪽의 학생 코드 (나)와 지도 코드 (다)를 대조했다.
1. switch 문은 20% 간격으로 case를 나누므로 ㉠은 cRate / 20이다. 정수 75/20은 3이어서 case 3부터 실행된다.
2. 학생 코드에는 case 3, 2, 1 뒤에 break가 없다. 그러므로 cRate=75일 때 case 3의 Green, 이어 case 2의 Yellow, 이어 case 1의 Red를 순서대로 출력한다(각 줄마다 줄바꿈).
3. 지도 코드에서 올바른 해당 범위 색상만 출력하도록 각 case 뒤의 ㉡은 break이다. ㉢은 case 1 대신 놓이는 default:로, 0~19%가 Red를 출력하게 한다. 다만 유효 입력 범위가 0~100%라는 전제에 의존한다.
4. 교육적 핵심은 switch 문이 조건 일치 지점에서 시작해 break를 만나기 전까지 아래 case를 연속 실행하는 fall-through 동작을 구별하는 것이다.
