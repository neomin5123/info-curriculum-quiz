## 2018-A-09 (4점) — 평가 채점기준의 변별력

**기존 답안:** ① 기존 0점·3점의 이분법적 채점은 목표에 도달하지 못한 원인이 다른 A(반복 구조를 쓰지 않음)와 B(반복 구조를 쓰지만 반복 조건 오류)를 구별하지 못해 피드백에 활용하기 어렵다. ② ㉠(2점): 반복문을 사용했지만 반복 조건 등에 오류가 있어 1부터 10까지 순서대로 출력하지 못한 경우(B). ㉡(1점): 반복문은 사용하지 않았지만 1부터 10까지 숫자를 순서대로 출력한 경우(A). 이유: 평가 목표인 반복 구조 활용 여부를 우선 반영하되 프로그램 기능의 성취 여부도 구분하여 부분 점수를 부여한다.

**독립 상세 풀이**

1. 평가 목표는 단순 출력 여부가 아니라 반복 구조를 이용해 프로그램을 작성하는 능력이다. 학생 A는 반복문 없이 출력문을 열 번 나열하므로 출력 결과는 맞지만 목표의 핵심인 반복 구조를 충족하지 않는다. 학생 B는 for문의 초기값 i=1과 조건 i>=10이 동시에 주어진다. 처음부터 1>=10이 거짓이므로 반복 몸체는 0회 실행되며 출력도 없다. 이 코드는 실행 가능한 코드로 변환하여 조건 판정을 독립 확인할 수 있다.
2. 기존 채점표는 서로 다른 성취 상태를 모두 0점 처리해 진단과 구체적 피드백을 어렵게 한다. 3점: 반복을 사용하고 1~10을 순서대로 출력. 2점(㉠): 반복문을 사용했지만 반복 조건 등 오류로 요구 출력을 충족하지 못함. 1점(㉡): 반복문을 사용하지 않지만 1~10을 순서대로 출력. 0점: 둘 다 충족하지 못함.
3. 2점/1점 가중치는 학습목표인 반복 구조 활용을 결과 출력만 성공한 경우보다 우선하여 반영한다. 이와 다른 합리적인 부분점수 체계가 가능한지 공식 채점기준으로는 확인하지 못했다.

**검증:** 코드 실행 + 시험 원본 이미지

**한계:** 직접 실행으로 B의 무출력 확인, 표준 C의 main 반환형은 int로 정정하여 검산(시험지 void main 그대로 재현한 빌드 성공 여부와 별개).

## 2018-A-10 (4점) — 로봇 청소기 주행 알고리즘의 결함

**기존 답안:** 예상 답안(원문 순서도 분석). 문제점 ① ‘충돌 시 우회전, 아니면 직진’이라는 고정 규칙과 ‘출발 지점이면 좌회전’만으로는 내부 벽으로 분리된 모든 청소 칸의 방문을 보장하지 못한다. 피드백: 공간의 연결·벽 배치를 고려하여 미방문 영역을 확인하고 모든 칸에 도달하도록 이동 경로 및 회전 조건을 설계·검증한다. 문제점 ② 청소를 완료했는지 판정하는 조건과 ‘전원 off’ 동작이 없어 모든 구역을 청소한 뒤 정지한다는 요구조건을 충족하지 못한다. 피드백: 방문한 청소 칸의 상태 또는 미청소 칸 수를 이용한 완료 조건을 추가하고, 완료 시 전원 off 후 종료하도록 알고리즘을 수정한다.

**독립 상세 풀이**

1. 과제의 성공 조건은 전원 on부터 모든 청소 가능 칸 방문을 보장하고, 그 이후 전원 off로 종료하는 것이다. 원본 순서도는 '충돌?'에서 예이면 우회전하고 아니면 직진한 다음, '출발 지점?'에서 예이면 좌회전하여 다시 이동시키는 반복 구조이다.
2. 첫 문제는 청소 공간을 가로지르는 내부 벽/통로를 고려한 미방문 칸 확인 및 경로 완전성 보장이 없다. 충돌 회피나 출발점 도달 여부만으로 모든 칸을 청소했다고 결론 내릴 수 없다. 피드백: 구역별 방문 여부와 벽 위치를 표기해 전체 칸을 방문하도록 방향전환 규칙 또는 경로를 명시하고, 임의 이동이 아닌 실제 격자 위에서 모든 칸을 추적·검증한다.
3. 둘째 문제는 종료 조건과 '전원 off'가 누락되었다. 출발 지점에 도착하면 좌회전하는 것은 종료가 아니며 모든 공간 청소 여부와 논리적으로 동일하지 않다. 피드백: 미청소 칸이 0일 때 전원 off 및 종료 노드로 이동하도록 조건 분기한다.
4. 그림을 근거로 '정확히 몇 번 이동했는가'를 단정하려면 실제 순서도를 실행 추적해야 하므로, 여기서는 과제 충족의 필수 조건 2개에 한정했다.

**검증:** PDF 도형 직접 시각 대조

**한계:** 구체적 이동 횟수·유일 경로는 검증하지 않음; 공식 채점요소 미확인.

## 2018-A-11 (4점) — 정보과 교육과정 개정 순서

**기존 답안:** (1) 개정된 순서: (다) → (가) → (나) [2007 개정 → 2009 개정 → 2015 개정 정보과 교육과정]. (2) 공통적인 특징 ① 정보 처리 및 정보과학·정보기술의 기초 개념을 이해하고 활용하는 능력을 강조한다. ② 정보 처리·컴퓨터 관련 지식과 기술을 이용해 실생활의 문제를 창의적으로 해결하는 능력을 기르는 데 중점을 둔다.

**독립 상세 풀이**

1. (다)는 1·2·3단계로 나눈 '정보기기의 구성과 동작' 내용 체계와 '정보 처리의 기본 원리'를 제시한다. 이는 2007 개정 정보과 교육과정에 부합한다.
2. (가)는 중학교 1~3학년군, '정보과학과 정보윤리' 및 계산적 사고·정보윤리적 소양을 명시한 2009 개정 교육과정에 해당한다.
3. (나)는 영역·핵심 개념·일반화된 지식·내용 요소·기능 구조와 '정보문화소양·컴퓨팅 사고력·협력적 문제해결력'을 사용하므로 2015 개정 교육과정이다. 따라서 개정 순서는 (다)→(가)→(나)이다.
4. 공통 특징 예시는 ① 정보과학/정보 처리 기본 개념과 원리의 이해, ② 정보기술을 바탕으로 실생활 문제를 창의적으로 해결하는 능력의 강조이다. 각 개정의 표현과 영역 구획이 같다는 뜻은 아니며, 2015 개정의 '협력적 문제해결력'이 세 시기 모두에 명시됐다고 주장하면 오답 위험이 있다.

**검증:** 교육과정 고시 연혁/문항 인용 대조

**한계:** 2007·2009 개정 교육과정의 전체 원문을 이번 빌드에서 재입수해 조문별 직접 대조하지 못함.

## 2018-B-01 (4점) — 배열 실습의 단계적 계열화

**기존 답안:** 예상 답안: ㉠ 이미 작성된 배열 프로그램의 일부를 수정·보완하거나 오류를 찾아 고쳐 프로그램을 완성하는 활동. ㉡ 주어진 실생활 문제를 해결할 배열 알고리즘을 학습자가 직접 설계하고 프로그램으로 구현하는 활동. 학습자 개인차 대응 교수·학습 방법 ① 학습 수준에 따라 힌트·부분 완성 코드·확장 과제 등 과제의 난이도와 지원 정도를 달리하는 수준별 학습, ② 숙련 학생과 도움이 필요한 학생이 짝 또는 모둠을 이루어 프로그래밍 절차를 설명하고 함께 오류를 수정하는 동료 교수·협동학습(짝 프로그래밍 등).

**독립 상세 풀이**

1. 단계 1은 완성된 배열 코드 읽기/이해, 단계 3은 주어진 알고리즘을 코드로 구현, 단계 5는 문제 발견부터 설계·구현까지 학생이 자율 수행한다. 단계별 독립성·난이도·교수 지원의 감소를 기준으로 비어 있는 단계를 배치한다.
2. 단계 2(㉠)에는 완성 코드 일부를 수정하거나 오류를 찾아 고치는 제한적 코드 변경 활동이 적절하다. 단순 코드를 읽는 단계보다 요구되는 구성 활동이 많고, 새 알고리즘을 완전히 코드화하는 단계보다는 부담이 적다.
3. 단계 4(㉡)에는 주어진 생활 속 문제를 분석하고 배열을 이용한 알고리즘을 직접 설계·구현하는 활동을 배치한다. 단계 5와 달리 해결 문제의 발굴은 요구하지 않는다.
4. 개인차를 고려한 교수법으로 (i) 기초·확장 과제와 힌트 제공을 차등화하는 수준별 수업, (ii) 이해 수준이 다른 학생이 풀이 전략을 설명하고 도움을 주고받는 동료교수·협동학습(짝 프로그래밍)을 제안한다. 각각 학생별 지원량/상호설명의 차원에서 효과를 설명한다. 특정 교수법 2가지가 유일 공식 답은 아니다.

**검증:** 시험 과제 조건과 교수학습 계열성 논리 검토

**한계:** 개인차 대응 교수법은 복수 허용 가능, 공식 답안 미확보.

## 2018-B-08 (10점) — 2015 개정 역량 기반 정보교육 논술

**기존 답안:** 예상 모범 답안. 서론: 2015 개정 정보과 교육과정은 컴퓨터 활용 기능 습득 중심을 넘어 정보문화소양·컴퓨팅 사고력·협력적 문제해결력을 교과 역량으로 명시하고, 정보윤리와 실생활 문제해결을 통합해 교육하도록 강조하였다. 본론: 총론의 ‘지식정보처리 역량’과 특히 연계되는 하위 요소로 ‘정보기술활용능력’ 및 ‘추상화 능력’을 선정할 수 있다. 정보기술활용능력은 필요한 자료를 수집·처리·표현하는 데 유용하며, 추상화 능력은 문제를 분해하고 핵심 요소를 찾아 해결 가능한 모델로 나타내도록 하기 때문이다. 또한 ‘자동화 능력’은 알고리즘을 프로그래밍해 모델을 실행·검증하는 데 기여한다. 타 교과 활용 예: 과학에서 기온·강수량 등 자료를 수집해 표로 정리하고, 패턴을 분석하여 예측 규칙을 만든 다음 프로그램으로 시뮬레이션한다. 이때 자료 처리, 추상화·자동화 및 모둠 내 결과 공유에 정보과 역량이 필요하다. 결론: 정보 교육 강화를 위해 타 교과와 연계한 실제 데이터를 활용하는 프로젝트 수업을 확대하고, 교사의 정보교육·프로그래밍 연수와 실습 환경을 지원하며, 최종 프로그램뿐 아니라 분석·설계·협력의 과정도 평가하도록 한다.

**독립 상세 풀이**

서론. 2015 개정 정보과 교육과정은 정보문화소양·컴퓨팅 사고력·협력적 문제해결력을 교과 역량으로 명시하고, 디지털 정보의 윤리적 활용과 프로그래밍을 통한 문제해결, 온라인 공동체 협업의 연계를 강조한다. 단순 조작기능의 폐기를 선언한 것은 아니므로 이전 개정에 전혀 없던 요소라는 단정은 피한다.
본론 1. 총론의 지식정보처리 역량은 다양한 분야의 지식과 정보를 수집·처리·활용해 문제를 합리적으로 해결하는 능력이다. 정보문화소양의 '정보기술활용능력'은 자료 수집·가공 및 정보 관리 측면에서, 컴퓨팅 사고력의 '추상화 능력'은 복잡한 문제를 핵심 요소로 분해·모델링하는 측면에서, '자동화 능력'은 분석된 해결 모델을 프로그램으로 구현·검증하는 측면에서 적합하다. 요구는 하위 요소를 '선정하고 이유'를 밝히는 것이므로 모든 하위 요소를 나열하는 식 답변은 불필요하다.
본론 2. 타 교과 사례로 과학 기온 자료를 조사·구조화한 후 이상치를 검사하고, 간단한 규칙을 도출해 프로그래밍으로 반복 분석하며, 팀원과 결과를 공유하는 활동을 제시한다. 데이터 처리(정보기술활용), 규칙 도출(추상화), 반복 실행(자동화), 결과 공유(디지털 의사소통)의 대응이 설명되어야 한다.
결론. 정보 교과 교육 강화 방안으로 실생활 데이터 기반 교과 간 프로젝트, 교사 연수, 컴퓨팅 환경의 개선, 결과뿐 아니라 분석·설계·협력 과정에 관한 수행평가를 병행하도록 제안한다. 단순 장비 확대만으로 역량이 신장된다고 단정하지 않는다. 본 답안은 논술 예시이고 공식 채점기준이 아니다.

**검증:** 시험에서 인용한 2015 개정 총론·정보과 별책10 직접 근거

**한계:** 교과 간 연계 사례 및 정책 제언은 구성한 예시이며 독립 공식 정답 아님.
