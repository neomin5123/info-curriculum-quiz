# v9.0.44 Retry Context / Acknowledge Audit

- Build: `9.0.44-study-rc.1`
- Curriculum data: unchanged (`270` official lines, `370` presentation units)
- Retry metadata now resolves from the actual source line family. Example: `데이터 · 과정·기능` instead of the aggregate selector label `내용체계 + 성취기준`.
- Achievement-standard cards keep the standard code in the original sentence context.
- New misses from unordered/group recall are scheduled as one-at-a-time single retry cards, not whole-set rewrite cards.
- Legacy persisted set retries are split into individual retry cards on startup.
- If the original expected answer equals a long official line, retry first uses a smaller presentation unit; when none exists, it falls back to a policy-backed suppressed fragment. It no longer says `전체를 다시 작성하세요`.
- Retry grading no longer auto-advances after one second. Result toast (`재인출 실패`, `표현 확인 필요`, `재인출 완료 ✓`) is transient, while the card stays open.
- Wrong/near retry requires explicit `확인` or `나중에` before the card closes. Correct retry requires `확인`.
- Outside-click / close-X cannot dismiss a card while a graded result is awaiting acknowledgement.

Regression suite: `npm test` PASS.
